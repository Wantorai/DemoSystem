# Постоянные статусы отправки в room-чатах

Новые страницы диагностики/сбор отчётов/админские команды очистки не добавлены. Существующая диагностика и Diag10 не изменены.

## Мобильное приложение

Под исходящими pending/sending/failed в RoomMessageRow показана постоянная подпись. Failed отображается как «Не отправлено» с существующим действием повторной отправки. Отключённая сеть для pending/sending даёт «Ожидает подключения». Отсутствующий локальный файл или соответствующая ошибка дают «Файл недоступен, выберите его заново» без бессмысленной кнопки повтора для той же записи.

Компонент подписывается на состояние сети только для отображаемых неотправленных сообщений. Наличие локального file:// проверяется при появлении/изменении сообщения, без опроса по таймеру и скачивания вложений. Ошибка проверки файла сама по себе не считается доказанным отсутствием. Успешно отправленные/удалённые сообщения не получают эту подпись. Старый failed при отключении сети остаётся failed — его прошлую ошибку не подменяем ожиданием.

В воркере потеря сети во время неуспешной попытки сохраняет pending и не расходует бюджет этой попытки. Отказы сервера, не допускающие retry, сохраняют прежнее поведение. Большой исправный failed в очереди исключён из планирования и не блокирует следующие отправки; это проверено отдельно. Ошибки повреждения хранилища — иной класс проблем, эта проверка не гарантирует отсутствие любых тормозов.

## Веб

Для нового room-текста создаётся локальная строка; при отказе она остаётся с подписью, текст ввода не очищается. Повтор из поля ввода для того же текста/ответа использует прежний clientId (сервер уже поддерживает идемпотентность). HTTP/socket-подтверждение убирает локальную строку. При отсутствии сети подпись сообщает об ожидании подключения; повторная отправка выполняется пользователем, новая фоновая веб-очередь не реализована.

При ошибке загрузки вложения локальная строка больше не исчезает. Blob URL сохраняется до ухода из чата; после утраты браузерного blob показывается просьба выбрать файл заново. Выбор вложения для повтора выполняется вручную. Локальное неотправленное сообщение удаляется локально, без DELETE по несуществующему серверному ID.

Статусы веб-ошибок используют существующий жизненный цикл сообщений/кэша страницы, а не отдельную долговечную очередь. Первоначальная загрузка истории и вытеснение старых локальных строк не изменены.

## Проверки

- `node docs/test-delivery-labels.cjs`: подписи offline/pending/sending/failed/missing-file, отсутствие подписи для sent/deleted.
- `node docs/test-delivery-worker.cjs`: failed с текстом 1 МБ не блокирует следующее сообщение и не отправляется автоматически; потеря сети на последней попытке сохраняет pending и счётчик; существующие тесты видео, повторов, watchdog и гонок.
- `node docs/test-web-delivery-status.cjs`: сохранение текста и локальной строки при отказе, повтор с тем же clientId, удаление временной строки при успехе, offline, пустой ответ сервера.
- ESLint веба без замечаний. Мобильные изменённые файлы: 0 ошибок, предупреждение о существующем BOM в outboxWorker.ts.

Проверки выполнены с подставными сетью/хранилищем. Визуальная проверка на телефоне/в браузере и публикация обновления не выполнялись.
