# Непрослушанные голосовые в room-чатах

Функция работает в мобильном приложении (`MobileApp/mobile-app`) и веб-чате `/webchats/room/:id`.
Счётчик индивидуален для пользователя. Свои сообщения, удалённые сообщения и вся история до включения функции исключаются.

## Включение

1. Применить миграцию `20260914180000-create-room-voice-plays.js` стандартным `npx sequelize-cli db:migrate` в `crm-backend`.
2. Перезапустить обновлённый backend и развернуть frontend.
3. Выпустить обновление мобильного приложения.

Миграция сохраняет единую дату начала учёта в `room_voice_tracking_start`. Она не меняется при перезапуске, входе пользователя или обновлении приложения. Старые сообщения не нужно массово помечать прослушанными. Голосовые, отправленные после миграции, участвуют в подсчёте. Старые версии клиентов не передают отметки воспроизведения: для корректного учёта нужно обновить клиенты.

Миграция и публикация обновлений в рамках разработки не выполнялись.

## Поведение и API

- `GET /api/rooms/:roomId/voices/unplayed?before=:messageId` возвращает `{count, nextMessageId}`. Счётчик охватывает всю подходящую историю. Кнопка перебирает сообщения по убыванию ID и возвращается к самому новому, когда достигнут конец.
- `PUT /api/rooms/:roomId/voices/:messageId/played` фиксирует первое воспроизведение. Повторы безопасны: уникальный ключ `(userId, messageId)`.
- Обе операции требуют активного участия в room-чате. `userId` берётся только из авторизации.
- Событие `roomVoicePlayed` отправляется в socket-комнату `user:<id>` для обновления остальных устройств и вкладок этого пользователя.
- Веб-клиент использует событие `playing`, мобильный — активное воспроизведение с начавшимся прогрессом. Переход и загрузка файла сами по себе не меняют отметку.
- Неподтверждённые сервером отметки сохраняются локально как ID. Повторная отправка выполняется при открытии соответствующего чата и восстановлении соединения/активности.
- Подсветка и загрузка контекста используют существующие механизмы перехода к сообщению.

Нет периодического опроса. События обновления счётчика объединяются на 400 мс. Для подсчёта не загружаются тексты и аудиофайлы. В БД используется частичный индекс голосовых по комнате и дате, отметки имеют составной первичный ключ.

## Проверки

- 6 Jest-проверок backend: доступ, валидация, ограничения выборки, собственные/удалённые сообщения, повторные отметки и socket-адресат, ошибки БД.
- Проверки клиентских компонентов с подменой React/native/browser/API: навигация без отметки, фактическое воспроизведение, отсутствие дублей, сохранение при отсутствии сети, повторная отправка и обновление через socket.
- TypeScript мобильного проекта и ESLint изменённых файлов. Проверки на физическом телефоне и живой PostgreSQL не выполнялись.
