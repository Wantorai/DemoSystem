# Настройки и справочники

## Каталог конфигураций

**Адрес:** `/config`. **Исходник:** [config/page.js](../../crm-fronend/src/app/config/page.js).

Страница собирает доступные пользователю настройки в одном месте. Ссылки загружаются через `/config-links?roleId=...`; дополнительно запрашивается системная информация и используется счётчик непросмотренных обращений поддержки. Состав каталога зависит от роли и серверных настроек.

**Показ:** доступные группы настроек. **Текст для видео:** «Конфигурации собраны в отдельном разделе. Пользователь видит те инструменты настройки, которые доступны его роли».

## Справочник Fields

**Адрес:** `/config/Fields`. **Исходник:** [Fields/page.js](../../crm-fronend/src/app/config/Fields/page.js).

Справочник позволяет добавить именованное значение и открыть существующую запись. Страница получает список через `/fields`, создаёт запись запросом `POST` и направляет в `/field/[id]`. Значения используются в формах заказных позиций. Конкретное бизнес-название справочника следует согласовать с терминологией компании; его не нужно путать с конструктором динамических полей `MainModel`.

**Показ:** добавление учебного значения и переход к нему. **Текст для видео:** «Общие справочники дают сотрудникам согласованный набор значений для заполнения рабочих форм».

## Карточка значения Fields

**Адрес:** `/field/[id]`. **Исходник:** [field/[id]/page.js](../../crm-fronend/src/app/field/[id]/page.js).

Позволяет изменить название значения, сохранить его, удалить или вернуться к справочнику. По идентификатору используются запросы чтения, `PUT` и `DELETE` к `/fields/:id`.

**Показ:** изменение названия учебной записи. **Текст для видео:** «Каждое справочное значение можно поддерживать в актуальном состоянии через отдельную карточку».

## Поставщики фурнитуры

**Адрес:** `/config/FurnVendors`. **Исходник:** [FurnVendors/page.js](../../crm-fronend/src/app/config/FurnVendors/page.js).

Список поставщиков фурнитуры с формой добавления по названию. Данные читаются и создаются через `/furnVendors`; выбор строки открывает карточку. Справочник используется при заполнении связанных позиций заказа.

**Показ:** список и форму добавления. **Текст для видео:** «Поставщики фурнитуры выбираются из общего справочника, чтобы использовать одинаковые названия во всех заказах».

## Карточка поставщика фурнитуры

**Адрес:** `/furnVendor/[id]`. **Исходник:** [page.js](../../crm-fronend/src/app/furnVendor/[id]/page.js).

Редактирование названия и удаление поставщика через `/furnVendors/:id`, с возвратом к общему списку. Это компактная React-форма с загрузкой текущих данных и сообщениями об ошибках сохранения.

**Показ:** карточку тестового поставщика. **Текст для видео:** «Карточка позволяет обновить название поставщика в справочнике».

## Поставщики фасадов

**Адрес:** `/config/FasadVendors`. **Исходник:** [FasadVendors/page.js](../../crm-fronend/src/app/config/FasadVendors/page.js).

Отдельный список поставщиков фасадов. Пользователь добавляет название и открывает существующую запись. Реализация использует `/fasadVendors` и переход в `/fasadVendor/[id]`; форма позиции заказа получает эти значения как справочные.

**Показ:** выбор категории поставщиков. **Текст для видео:** «Поставщики разделены по назначению, чтобы в рабочей форме выбирать подходящее значение».

## Карточка поставщика фасадов

**Адрес:** `/fasadVendor/[id]`. **Исходник:** [page.js](../../crm-fronend/src/app/fasadVendor/[id]/page.js).

Позволяет прочитать, изменить или удалить запись поставщика фасадов. Для операций используется `/fasadVendors/:id`; после удаления предусмотрен возврат к справочнику.

**Показ:** название и действия карточки. **Текст для видео:** «Для каждого поставщика есть отдельная форма редактирования».

## Подрядчики

**Адрес:** `/config/WorkVendors`. **Исходник:** [WorkVendors/page.js](../../crm-fronend/src/app/config/WorkVendors/page.js).

Справочник исполнителей работ со стороны подрядчиков. Поддерживает просмотр списка и добавление названия через `/workVendors`. Записи используются наряду с поставщиками фурнитуры и фасадов в производственных формах.

**Показ:** список подрядчиков. **Текст для видео:** «Работы внешних подрядчиков также можно связывать с единым справочником исполнителей».

## Карточка подрядчика

**Адрес:** `/workVendor/[id]`. **Исходник:** [page.js](../../crm-fronend/src/app/workVendor/[id]/page.js).

Форма изменения названия, удаления и возврата к списку. Чтение и запись выполняются через `/workVendors/:id` с обработкой состояния загрузки и ошибок.

**Показ:** карточку учебного подрядчика. **Текст для видео:** «Сведения справочника можно корректировать отдельно от самих заказов».

## Источники обращений

**Адрес:** `/config/InfoSources`. **Исходник:** [InfoSources/page.js](../../crm-fronend/src/app/config/InfoSources/page.js).

Список источников, из которых приходят обращения. Здесь добавляются новые названия и открываются существующие записи. Страница использует `/infoSources`; этот же справочник загружается в формах консультаций.

**Показ:** источник в справочнике и затем в форме консультации. **Текст для видео:** «Для обращения можно указать источник из общего списка, чтобы сведения заполнялись единообразно».

## Карточка источника обращения

**Адрес:** `/infoSource/[id]`. **Исходник:** [page.js](../../crm-fronend/src/app/infoSource/[id]/page.js).

Позволяет изменить название источника или удалить его. Данные загружаются и сохраняются через `/infoSources/:id`; есть возврат к списку.

**Показ:** редактирование тестового названия. **Текст для видео:** «Список источников можно обновлять по мере изменения каналов привлечения клиентов».

## Типы оплаты

**Адрес:** `/config/Paylists`. **Исходник:** [Paylists/page.js](../../crm-fronend/src/app/config/Paylists/page.js).

Справочник типов оплаты с добавлением значений и переходом к карточке. Использует `/paylists`; значения подгружаются в заказы и другие связанные представления. Это справочник, а не самостоятельная бухгалтерия или платёжный шлюз.

**Показ:** список вариантов. **Текст для видео:** «Тип оплаты выбирается из общего справочника и становится частью данных заказа».

## Карточка типа оплаты

**Адрес:** `/paylist/[id]`. **Исходник:** [page.js](../../crm-fronend/src/app/paylist/[id]/page.js).

Изменение названия, сохранение, удаление и возврат к перечню типов оплаты. Страница работает с `/paylists/:id`.

**Показ:** форму редактирования. **Текст для видео:** «Состав справочника типов оплаты поддерживается через простые карточки».

## Технологи

**Адрес:** `/config/Technics`. **Исходник:** [Technics/page.js](../../crm-fronend/src/app/config/Technics/page.js).

Таблица настроек технологов: телефон, цвет, возможность видеть все заказы и всех в CRM. Список загружается из `/technics`, изменения строки сохраняются через `PUT /technics/:id`. Это настройка уже представленных в списке сотрудников, а не основная форма создания учётной записи.

**Показ:** цвет и параметры видимости одного сотрудника. **Текст для видео:** «Для технологов настраиваются контактные данные, визуальное обозначение и охват рабочих данных».

## Менеджеры

**Адрес:** `/config/Managers`. **Исходник:** [Managers/page.js](../../crm-fronend/src/app/config/Managers/page.js).

Список менеджеров позволяет редактировать телефон и признак «Видеть всё». Данные читаются через `/managers`, сохранение выполняется по строке через `/managers/:id`.

**Показ:** параметры менеджера. **Текст для видео:** «Для менеджеров предусмотрены отдельные рабочие настройки, включая охват доступных данных».

## Установщики

**Адрес:** `/config/Installers`. **Исходник:** [Installers/page.js](../../crm-fronend/src/app/config/Installers/page.js).

Настраиваются признак «Работает», телефон, цвет и порядок установщиков. Порядок меняется кнопками перемещения вверх и вниз. Запросы направляются в `/installers`; изменение позиции сохраняет порядок затронутых записей.

**Показ:** цвет и порядок строк. **Текст для видео:** «Справочник установщиков связан с графиком работ. Здесь можно настроить их порядок и визуальное различение».

## Основная модель заказа

**Адрес:** `/config/MainModel`. **Исходник:** [MainModel/page.js](../../crm-fronend/src/app/config/MainModel/page.js).

Экран конфигурации параметров основной модели: техническое имя, отображаемая подпись, ширина и другие свойства. Поддерживает добавление, изменение и удаление параметров. Загружает `/mainModel` и связанную конфигурацию; также содержит синхронизацию списка параметров для механизма прав.

**Показ:** один существующий параметр и его подпись в заказе. **Текст для видео:** «Структура заказа описана в конфигурации. Названия и свойства параметров используются при построении рабочих экранов».

## Поля CRM

**Адрес:** `/config/crmConfig`. **Исходник:** [crmConfig/page.js](../../crm-fronend/src/app/config/crmConfig/page.js).

Редактор полей консультаций: техническое имя, подпись, ширина, порядок, тип и значение по умолчанию. Варианты типов включают текст, число, дату со временем, дату и чекбокс. Чтение и изменения выполняются через `/crm-config`.

**Показ:** связь параметра конфигурации и поля консультации. **Текст для видео:** «Поля CRM можно настраивать отдельно от страниц, определяя их порядок, типы и подписи».

## Статусы CRM

**Адрес:** `/config/crmStatuses`. **Исходник:** [crmStatuses/page.js](../../crm-fronend/src/app/config/crmStatuses/page.js).

Настройка ключа, названия, цвета и порядка статусов консультаций. Поддерживаются создание, изменение, удаление и перестановка через `/crm-statuses`.

**Показ:** перечень этапов и соответствующие цвета в CRM. **Текст для видео:** «Этапы обработки обращения задаются в справочнике статусов и используются в рабочей таблице».

## Статусы заказов

**Адрес:** `/config/OrderStatuss`. **Исходник:** [OrderStatuss/page.js](../../crm-fronend/src/app/config/OrderStatuss/page.js).

Управление отдельным набором статусов заказов: название, ключ, редактирование, удаление и порядок. API — `/statuses`, включая `/statuses/order-update`. Это другой справочник, чем статусы CRM.

**Показ:** один статус и его использование в заказе. **Текст для видео:** «Для заказов предусмотрен собственный набор состояний, соответствующий процессу их выполнения».

## Цвета состояний

**Адрес:** `/config/StatusColors`. **Исходник:** [StatusColors/page.js](../../crm-fronend/src/app/config/StatusColors/page.js).

Экран задаёт цветовое оформление состояний с использованием списка статусов и `/status-colors`. Эти настройки загружаются рабочими представлениями, в том числе графиком и карточкой заказа.

**Показ:** настройку и соответствующее выделение. **Текст для видео:** «Цвета помогают быстрее различать состояния в таблицах и графике».

## Рабочие и выходные дни

**Показ:** одну дату и её тип. **Текст для видео:** «Рабочий календарь позволяет учитывать выходные и исключения при работе с датами».

**Адрес:** `/config/Schedule`. **Исходник:** [Schedule/page.js](../../crm-fronend/src/app/config/Schedule/page.js).

Страница «Фильтр данных для работы графика» связывает настройки графика с параметрами основной модели. Загружает `/mainModel` и `/schedule`, а изменения сохраняет через `/schedule`.

**Показ:** строку события и её настройку. **Текст для видео:** «Можно настроить, какие сведения отображаются непосредственно в событии графика и как они сгруппированы».

**Адрес:** `/config/eventInfos`. **Исходник:** [eventInfos/page.js](../../crm-fronend/src/app/config/eventInfos/page.js).

**Показ:** параметр с флажком «Включено». **Текст для видео:** «Состав дополнительных сведений о событии тоже определяется настройками».

## Настройка отчётов

**Адрес:** `/config/dashbord`. **Исходник:** [dashbord/page.js](../../crm-fronend/src/app/config/dashbord/page.js).

Создание, редактирование и удаление конфигураций дашборда. Настраиваются источник данных и параметры серий; доступные поля запрашиваются для выбранного источника. Используется `/dashboard-configs` и его маршрут `/fields/:endpoint`.

**Показ:** существующий отчёт и соответствующий график. **Текст для видео:** «Отчёт сначала описывается в конфигурации, после чего дашборд использует её для получения и отображения данных».

## Оформление и планировщик задач

**Адрес:** `/config/Styles`. **Исходник:** [Styles/page.js](../../crm-fronend/src/app/config/Styles/page.js).

Страница объединяет размер текста, основные цвета системы и управление системными задачами. В разделе планировщика доступны параметры заданий, история запусков и запуск по запросу. Это существенная особенность: экран не ограничивается визуальными стилями.

Оформление загружается через `/app-style`, сохраняется через `/admin/app-style` и применяется общим загрузчиком. Планировщик использует `/admin/scheduler/jobs`, маршруты истории и `run-now`.

**Показ:** цвета и размер текста; задания — в режиме просмотра. **Текст для видео:** «Внешний вид приложения настраивается централизованно. Здесь же доступны инструменты обслуживания и история выполнения фоновых задач».
