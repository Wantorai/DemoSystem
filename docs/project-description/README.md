# Описание проекта OrderSpace CRM

OrderSpace CRM объединяет работу с обращениями клиентов, заказами, производственными позициями, графиком установок, перепиской и файлами. Основной рабочий процесс связывает менеджеров, технологов, установщиков и сотрудников, контролирующих выполнение заказа.

Это рабочая версия описания для редактирования и подготовки видеопрезентации. Она отражает код репозитория на 19 ноября 2026 года. Описания экранов составлены по страницам, компонентам и связанным серверным модулям; запуск приложения и проверка интеграций на действующем сервере в эту работу не входили.

В каждой карточке есть назначение, функции, объяснение реализации и идея демонстрации. Фрагменты «Текст для видео» можно адаптировать под собственную речь. `[id]` в адресе обозначает идентификатор выбранной записи, а не буквальную часть пользовательского URL.

## Какую задачу решает система

Информация о заказе распределяется между несколькими рабочими представлениями. Менеджер работает с обращением и контактами, технолог — с консультацией и подготовкой, установщик — с графиком, а производственные сотрудники — с позициями и готовностью. Общие записи позволяют переходить от списка к подробной карточке и видеть связанные сведения.

Сильная сторона реализации — настраиваемая структура. Состав полей, подписи, порядок колонок, статусы и доступы вынесены в отдельные конфигурации. Поэтому описание конкретного рабочего места зависит от настроек и роли пользователя. Возможность добавлять параметры не означает, что любое изменение бизнес-логики выполняется без программирования.

## Как устроен проект

| Часть | Реализация | Назначение |
| --- | --- | --- |
| Веб-интерфейс | Next.js App Router, React; `crm-fronend/src/app` | Страницы и переходы между ними |
| Общие компоненты | `crm-fronend/src/components` | Формы, навигация, чаты, уведомления и повторно используемые элементы |
| Авторизация | `AuthContext`, `ProtectedLayout`, серверные модули авторизации | Сессия пользователя и доступ к разделам |
| Сервер | Node.js, Express; `crm-backend/routes`, `controllers`, `services` | API, обработка действий и интеграции |
| Данные | PostgreSQL и Sequelize | Модели клиентов, заказов, пользователей, переписки и настроек |
| Обмен событиями | Socket.IO | Обновления переписки и связанные события |
| Фоновые операции | `crm-backend/workers`, очереди и планировщики | Напоминания, отложенные сообщения, обработка аудио и обслуживание файлов |
| Windows-клиент | `filespace-desktop` | Синхронизация файлового пространства с локальной папкой |
| Публикации | `socdep-api` | Отдельный API для Social Deploy |

Конкретные версии зависимостей находятся в [frontend package.json](../../crm-fronend/package.json) и [backend package.json](../../crm-backend/package.json). Подключение базы задано в [database.js](../../crm-backend/config/database.js). В репозитории также есть Docker Compose, конфигурация PM2, скрипты развёртывания и резервного копирования. Они относятся к эксплуатации, а не к пользовательским страницам.

## Общие принципы интерфейса

- Списки дают обзор, поиск и переход к конкретной записи.
- Карточки служат для подробной работы с одной сущностью.
- Справочники обеспечивают единообразный выбор сотрудников, поставщиков, статусов и других значений.
- Конфигурации определяют структуру рабочих экранов; права определяют доступ пользователя.
- Сообщения о загрузке и ошибках помогают понять результат обращения к серверу.

В приложении используются собственные CSS-файлы, Tailwind, FullCalendar для календарей и Recharts для отчётных графиков. Многие страницы — клиентские React-компоненты, которые загружают данные через `fetch` или Axios. Небольшой `page.js` иногда только подключает форму: основная реализация при этом находится в `src/components`.

## Что уточнить при редактуре

Уточни публичное название продукта, целевую аудиторию и используемые в компании термины. В частности, справочник `Fields` лучше назвать в презентации так, как его называют сотрудники: одного технического имени недостаточно для уверенного определения бизнес-смысла.

Для финальной версии добавь собственную историю создания: исходную проблему, свою роль, этапы разработки и реальные результаты внедрения. Код показывает устройство системы, но не подтверждает авторство отдельных решений, число пользователей или экономию времени. Такие сведения в описание не выдуманы.
