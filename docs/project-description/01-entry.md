# Вход и общая оболочка

## Страница авторизации

**Адрес:** `/login`. **Исходник:** [login/page.js](../../crm-fronend/src/app/login/page.js).

### Для чего нужна

Страница служит входом сотрудника в CRM. Она принимает имя пользователя и пароль, передаёт их серверу и сообщает результат проверки. После получения сессии приложение загружает сведения о пользователе и разрешённые ему разделы.

### Что видит пользователь

В центре экрана расположена карточка «Вход в систему» с двумя обязательными полями и кнопкой «Войти». Пароль скрыт при вводе. Во время отправки кнопка блокируется и показывает «Вход…». Ошибка выводится под формой, поэтому пользователь может исправить данные и повторить попытку.

### Какие функции выполняет

- Ввод имени и пароля с поддержкой автозаполнения браузером.
- Проверка заполнения обязательных полей стандартными средствами формы.
- Отправка запроса на авторизацию.
- Защита от повторной отправки, пока предыдущая попытка не завершилась.
- Отображение ошибок учётных данных, серверного ответа и сетевого соединения.
- Передача полученного токена общему модулю авторизации.
- Удобный ввод на сенсорных устройствах.

### Как реализована

Это клиентский React-компонент. `useState` хранит введённые значения, ошибку и состояние загрузки. `useRef` хранит признак уже выполняющейся отправки: он позволяет остановить повторный запрос сразу, не ожидая перерисовки кнопки.

Обработчик `handleLogin` отменяет стандартную перезагрузку формы и отправляет `POST /auth/login` с JSON, содержащим `username` и `password`. При успешном ответе он получает токен и вызывает `login` из [AuthContext.js](../../crm-fronend/src/context/AuthContext.js). При неудаче форма читает сообщение сервера или показывает предусмотренный текст ошибки. После завершения запроса блокировка отправки снимается.

На сервере [authController.js](../../crm-backend/controllers/authController.js) ищет пользователя по имени, проверяет пароль через `bcrypt.compare` и формирует JWT. Для неверного имени и неверного пароля используется одинаковый ответ 401. Сам пароль не сохраняется в состоянии авторизации браузера.

`AuthContext` сохраняет токен в `localStorage`, запрашивает `/auth/me`, разрешения роли и список ресурсов. При повторном открытии приложения он восстанавливает авторизацию по сохранённому токену. [ProtectedLayout.js](../../crm-fronend/src/components/ProtectedLayout.js) проверяет доступ к текущему пути: без токена направляет на вход, а при отсутствии разрешения — на `/403`. Клиентская проверка отвечает за поведение интерфейса; серверные проверки API являются отдельным уровнем.

### Оформление и удобство

[login.css](../../crm-fronend/src/app/login/login.css) задаёт светлый фон, белую карточку шириной до 420 пикселей, скругления, тень и выделение активного поля. Карточка подстраивается под ширину экрана. Поля и кнопка имеют минимальную высоту 44 пикселя; размер текста в полях — 16 пикселей.

У полей есть доступные названия `aria-label`, а у формы — `aria-busy`. Для имени отключены автоматическая коррекция и изменение регистра. Обработчики касаний различают короткое нажатие и движение пальца, чтобы прокрутка не переводила фокус в поле случайно.

### Что показать в видео

Открыть страницу, кратко объяснить назначение двух полей, показать реакцию на ошибку и затем успешный вход тестовым пользователем. Для короткой презентации достаточно одного успешного входа и пояснения, что доступ определяется ролью.

**Текст для видео:** «Работа начинается со страницы авторизации. Сотрудник входит под своей учётной записью, после чего система загружает его профиль и доступные разделы. Форма сообщает об ошибках и блокирует повторную отправку во время проверки. Интерфейс адаптирован и для компьютера, и для телефона».

### Примечание перед записью

Сейчас есть два перехода после входа: страница вызывает `router.push('/main')`, а асинхронный `login` в контексте после загрузки разрешений вызывает `router.replace('/')`. При этом страница не ожидает завершения `login`. Поэтому нельзя обещать в рассказе, что пользователь всегда остаётся на графике. Фактический конечный экран следует проверить перед записью; в рамках подготовки документации код не менялся.

## Стартовая страница и установка приложений

**Адрес:** `/`. **Исходник:** [app/page.js](../../crm-fronend/src/app/page.js).

Страница предлагает установку мобильного приложения и FileSpace для Windows. Она получает версии сборок с сервера, показывает кнопки загрузки, состояние процесса и ошибки. Мобильная сборка скачивается как APK, Windows-клиент — как EXE. Для скачивания используется токен текущего пользователя.

Загрузка реализована через `fetch`. При наличии потока ответа приложение читает его частями и рассчитывает прогресс, если сервер сообщил размер. После получения данных создаётся временная ссылка на файл. На этой же странице подключён [SupportTicketPanel](../../crm-fronend/src/components/SupportTicketPanel.jsx), через который сотрудник работает с обращениями в поддержку.

**Показ:** версии приложений, две карточки загрузки и блок поддержки. **Текст для видео:** «Веб-система связана с приложениями для сотрудников. Здесь можно получить актуальную сборку и обратиться в поддержку».

## Общая оболочка приложения

**Исходники:** [layout.js](../../crm-fronend/src/app/layout.js), [Header.js](../../crm-fronend/src/components/Header.js), [ProtectedLayout.js](../../crm-fronend/src/components/ProtectedLayout.js).

Оболочка связывает страницы с общим контекстом авторизации, навигацией, стилями и всплывающими уведомлениями. Здесь подключаются локализация интерфейса, загрузчик оформления, контекст маскирования данных и уведомления об обслуживании. Благодаря общей оболочке эти механизмы не требуется создавать заново на каждом экране.

**Показ:** переход между двумя доступными разделами с сохранением общей навигации. **Текст для видео:** «Все разделы объединены общей навигацией и системой доступа. Сотрудник работает в одной среде, переходя от списка к карточке и связанным инструментам».

## Доступ запрещён

**Адрес:** `/403`. **Исходник:** [403/page.js](../../crm-fronend/src/app/403/page.js).

Небольшая служебная страница сообщает, что у пользователя нет прав на просмотр раздела. Она содержит заголовок и пояснение; проверка доступа выполняется вне этой страницы, в общей оболочке.

**Показ:** можно использовать при объяснении ролей. **Текст для видео:** «Если раздел недоступен текущей роли, система показывает понятное сообщение об ограничении доступа».

## Файл политики конфиденциальности

В [privacy-policy/_page.js](../../crm-fronend/src/app/privacy-policy/_page.js) находится отдельный файл, но он назван `_page.js`, а не `page.js`. Поэтому он не включён в каталог действующих страниц App Router. Разрешение пути `/privacy-policy` в `ProtectedLayout` само по себе не делает этот файл страницей. Перед демонстрацией политики нужно отдельно проверить наличие рабочего маршрута.
